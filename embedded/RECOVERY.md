# 账号列表异常时怎么办

这份说明用于排查“账号列表无法读取”。应用升级只替换程序文件，不会自动恢复任何账号。

1. 先停止使用出问题的资料目录，正常退出使用它的软件。不要删除资料目录、`accounts.json`、`Sessions` 或任何旧临时文件，不要重新生成默认账号列表。
2. 请维护者先在本机非同步的私有位置保留整个资料目录原件，再检查磁盘空间、文件访问权限和账号列表格式。副本包含可用的登录 Cookie，不要放入 iCloud 同步桌面/文稿或网盘目录。复制、恢复或更改现有资料前应另行确认准确对象；本轮测试没有读或复制真实资料。
3. `accounts.json` 中每个账号的稳定 ID 对应 `Sessions` 下的目录。旧账号列表即使格式正确，也可能缺少后来新增的 ID；只凭格式检查通过，不能认定恢复完整。不要按昵称猜测对应关系、合并同名账号或删除多余目录。
4. 维护者可在源码的 `embedded/` 目录用 Node 运行只读检查工具：`node scripts/check-account-config.cjs --data-root /绝对路径/资料目录`。请只在自己的副本上运行；本轮只在新建的合成目录测试。它不创建 Store、不改文件、不读取登录态内容、不连接网站。输出只有状态、数量和固定警告码，不包含账号名、备注、ID、头像或目录路径。超过 16 MiB 的账号列表会标记未检查，这只是工具读取限制。
5. `ok` 仅说明当前元数据结构和可见目录名匹配；它不证明登录有效、账号身份正确或历史任务完整。账号从未打开时没有对应 Session 目录是正常情况。`warning` 要逐项人工核实，未完整检查时数量为 `null`；`error` 表示本工具不能确认列表有效。退出码依次为 0、2、1。

单个账号列表文件或 UI 文件在提交前保存失败时，该文件的上次值及相应内存状态保持不变；临时文件清理是尽力而为，若磁盘同时拒绝清理，可能留下本次创建的临时文件。不得批量清理旧文件。重命名是提交点，本补丁未增加断电持久性承诺或自动备份。原有 clearProfile 会先保存列表、再写 UI，两个文件不构成事务：第二步失败时第一步仍已生效，本补丁没有改变此行为。

已知原有限制：缺少 `accounts.json`（包括悬空链接）时，启动应用仍可能静默生成默认账号列表。若已有 `Sessions`，旧目录会与新 ID 不匹配。因此缺少配置时不要启动应用，也不要为检查而把列表移走后重启。只读工具报 `CONFIG_MISSING` 不表示可以安全新建；需维护者先核对原件。本轮不自动改变旧版的初始化或资料恢复行为。

恢复后的真实登录、六个不同身份和工作流程仍须由使用者亲自验收。请勿将账号目录上传至 GitHub 或发送给外部模型。
